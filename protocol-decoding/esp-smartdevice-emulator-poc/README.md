# ESP8266 bus PoC

Proof of concept for replacing the SmartDeviceBox with an Amica NodeMCU v2 (ESP8266EX). The target is the ESP8266; this
project emulates the SmartDeviceBox side. Entry point: `just` lists the recipes.
The opposite direction (emulating the freezer towards a real box) is `../esp-freezer-emulator-poc`.

## Phases

| Phase | Change | Goal |
|---|---|---|
| 1 | `esp-poc-phase1-listener` | passive listener, protocol core, comparison with the logic analyzer |
| 2 | `esp-poc-phase2-node02` | transmit as node `02` |
| 3 | `esp-poc-phase3-full-protocol` | full protocol |

Specs and design: `../../openspec/changes/<change>/`. Protocol knowledge: `../01-protocol.md` to `../05-bus-roles.md`.

## Layout

```

src/main.cpp          listener: ring buffer -> decode -> log/stats
test/test_core/       Unity tests, vectors.h (generated by tools/make_vectors.py)
tools/                make_vectors.py, compare.py
logs/                 board logs and exports (git-ignored)
```

## Wiring (phase 1)

```
 appliance pad 2 (bus) ──┬── box (unchanged)
                         ├── logic analyzer CH0
                         └── 4.7 kΩ ── D7 (GPIO13)  NodeMCU
 appliance GND pad ──────┴── LA GND ── NodeMCU GND
 NodeMCU D4 (GPIO2) ── jumper ── NodeMCU TX pin (GPIO1)      USB -> laptop
 pads 1, 3: not connected                                 D8: not connected
```

Console: UART1 TX on D4, jumpered to the `TX` header pin, so the CP2102 forwards it to USB at 115200.

### Safety
- Measure the voltage between appliance GND and laptop/USB GND before connecting. For the first contact, run the laptop on battery.
- Power the NodeMCU before plugging in D7. The 4.7 kΩ series resistor limits back-feed below 1 mA if it is not.
- Pads 1 and 3 are never connected. D8 (GPIO15) stays open in phase 1. The firmware never transmits.

## Bench procedure

1. `just flash`, attach as above, start `just log`, and send `v` for full output.
2. Start a Logic 2 Async Serial capture (57600 8N1, ≥ 60 s) at the same moment. Open and close the door, toggle SuperFrost once from the app.
3. Export the data table as hex into `logs/` (radix 3, path inside the repo). Run `just compare logs/<board>.log logs/<la>.csv`.
4. Capture 10 s without the board and compare with `cd .. && just slots <csv>`: BREAK, schedule and latency must be unchanged.
5. Run for 1 hour and check the `S` lines for overruns and resets.
6. Record the results in `../05-bus-roles.md` (section "ESP listener") and tick Phase 1 in `../potential-next-steps.md`.
